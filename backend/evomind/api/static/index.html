Model stability across time

The evaluation above uses one cutoff and a random file split — it tells you the model can guess held-out files correctly, not whether it still works after time passes. Rolling-origin (walk-forward) evaluation checks that directly: train at an earlier point in history, test purely on a later period the model never saw, repeated across cutoffs at 50% / 65% / 80% through the repo's history. Slower — repeats the full pipeline once per cutoff, so it's opt-in rather than run automatically.

# File Risk Trend Score
Risk = predicted probability of a bug-fixing commit in the model's labeling horizon, not a certainty. Fix commits are identified by a commit-message keyword heuristic, then traced back via SZZ (git blame on each fix's parent revision) to confirm the underlying defect actually existed as of the training cutoff — not a bug introduced later that a fix just happened to touch this file for. Still a heuristic pipeline end to end — treat scores as directional signal, not ground truth.
